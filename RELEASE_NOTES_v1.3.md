## 📋 Саммари изменений

### Архитектурные изменения

#### 1. Доменное разделение (sreda.pw ↔ go.sreda.pw)
**Проблема:** Оба домена показывали одинаковый контент, не было четкого разделения между брендом и продуктом.

**Решение:**
- Рефакторинг монолитного `fetch` handler в две функции:
  - `handleSreda()` — обработка `sreda.pw` и `www.sreda.pw`
  - `handleGo()` — обработка `go.sreda.pw` и workers.dev
- Строгая проверка hostname в entry point
- `sreda.pw` возвращает 404 для всех путей кроме `/` и статических ассетов

**Результат:**
- ✅ `sreda.pw` → SREDA brand landing (инфраструктурный узел)
- ✅ `go.sreda.pw` → ISKRA product pages (смартлинки, артисты, релизы)
- ✅ Четкое разделение ответственности

### Функциональные улучшения

#### 3. Страница списка артистов — полная оптимизация

**A. Сетка и размеры карточек (инфраструктурный стиль)**
- Строгая сетка: `repeat(4, minmax(176px, 1fr))` (карточки на ~20% меньше)
- Контейнер: `max-width: 900px`, симметричные отступы `1rem`
- Gap: `0.4rem` для плотной компоновки
- Карточки заполняют 100% ячеек сетки (без центрирования)
- Синхронизация: `.artists-grid` и `.artists-loading` идентичны

**B. Визуальное уменьшение веса карточек**
- Внутренний padding: `0.6rem` (было 0.75rem)
- Border radius: `12px` (было 16px)
- Мягкие тени и границы для легкого вида
- Результат: больше артистов помещается на один экран

**C. Обложки full-bleed (современный вид)**
- Обложки без внутренних отступов
- Placeholder как overlay (не отдельная рамка)
- Текст placeholder: `rgba(255,255,255,0.4)` для тонкости
- Скелетон соответствует финальной геометрии

**D. Мобильная оптимизация (max-width: 640px)**
- **Хедер**: скрыт подзаголовок, уменьшены отступы, поиск на всю ширину
- **Фильтры**: кнопка "Фильтры" (только мобильная), сортировка в dropdown
- **Карточки**: сетка 2 колонки, уменьшен вертикальный размер на ~15-20%
- **Иконка действия**: opacity `0.45` в покое, полная при взаимодействии
- **Результат**: быстрее сканирование, меньше когнитивной нагрузки

**E. Фото артистов**
- Карточки показывают `artist_photo_url` из шапки страницы артиста
- Fallback: если фото нет → обложка последнего релиза
- SQL оптимизация через CTE `artist_photos`
- Единообразие между списком и страницей артиста

**F. Синхронизация ширины**
- Хедер, сетка и пагинация имеют одинаковую ширину (`max-width: 900px`)
- Убраны пустые боковые "уши"
- Страница читается как системная панель
